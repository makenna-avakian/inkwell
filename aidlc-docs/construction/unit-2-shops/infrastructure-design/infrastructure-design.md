# Infrastructure Design — Unit 2: Shops & Commission Rules

See [shared-infrastructure.md](../../shared-infrastructure.md) for the R2 bucket/domain decisions (project-wide, decided here at Unit 2). This document covers Unit 2-specific mappings.

## Compute
- No dedicated compute — runs in the shared Next.js app on Vercel, same as Unit 1.

## Storage
- `shop_profiles`, `portfolio_images`, `commission_rule_versions`, `shop_commission_settings` tables in the shared Neon database.
- Images in the `inkwell-media` R2 bucket, under `{environment}/shops/{shopId}/{imageId}.{ext}` object keys.

## CORS Configuration (required for direct browser uploads)
The `inkwell-media` bucket must allow `PUT` requests from the app's own origin(s) (`http://localhost:3000` for dev, the Vercel preview/production domains) so the browser can upload directly to a presigned URL — otherwise the browser blocks the cross-origin PUT before it reaches R2.

## Networking
- Public reads: `media.inkwell.app` custom domain, mapped to the R2 bucket, allowlisted in `next.config.ts`'s `images.remotePatterns`.
- Uploads: authenticated via presigned URLs generated by the Next.js server (no public write access to the bucket).

## Monitoring
- Upload failures and presigned-URL-generation errors are captured by Sentry (shared-infrastructure.md), same as Unit 1's error tracking.
